4. Відповіді на запитання (Завдання 5)

1. У скільки разів Insert(0, x) повільніший за Add(x) - і чому саме так, виходячи з того, як список влаштований усередині?
Insert(0, x) працює приблизно у 1000-1500 разів повільніше, ніж Add(x).
Обґрунтування: List<T> у C# побудований поверх внутрішнього безперервного масиву. Додавання в кінець Add(x) має амортизовану складність O(1), оскільки елемент просто записується за вільним індексом. Вставка на початок Insert(0, x) має складність O(N), оскільки перед додаванням нового елемента система змушена фізично зсунути усі існуючі N елементів масиву на 1 позицію праворуч. Для 100 000 елементів це створює мільярди операцій переміщення пам'яті (O(N^2) загалом).

2. Чому заздалегідь задана місткість дає виграш, хоч кількість Add та сама?
Коли місткість (Capacity) не вказана, List<T> починає з малого масиву (зазвичай на 4 елементи). При його заповненні список створює новий масив удвічі більшого розміру, копіює туди всі існуючі елементи та видаляє старий. Для 100 000 елементів перевиділення пам'яті та копіювання відбувається близько 15 разів. Заздалегідь задана місткість new List<int>(100000) відразу виділяє необхідну пам'ять, виключаючи будь-які витрати на копіювання й релокацію.

3. Чому Contains тисячу разів помітно довший за сто тисяч Add?
Метод Contains реалізує лінійний пошук O(N): щоб переконатися, що елемента немає, він послідовно порівнює шукане значення з кожним із 100 000 елементів списку. Таким чином, 1 000 викликів Contains виконують 1000 x 100000 = 100 000 000 порівнянь у пам'яті
